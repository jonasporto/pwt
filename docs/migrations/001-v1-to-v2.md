# 001 — schema 1 → 2: JSON state becomes flat key=value

**Introduced by:** the next pwt release · **Applies to:** any install created before
`~/.pwt/state-version` existed · **Needs:** `jq`, for this one conversion only

## What changes

Internal state moves from JSON to flat `key=value` files, one file per
record. JSON does not disappear from pwt — it remains the *output* format
(`list --porcelain`, `state --json`, …), now produced without `jq`.

| Before (schema 1) | After (schema 2) |
|---|---|
| `meta.json` (all worktrees of all projects in one file) | `state/<project>/<worktree>.meta` — one file per worktree |
| `projects/<name>/config.json` | `projects/<name>/config` (dotted keys: `editor.default=vim`) |
| `projects/<name>/gateway.json` | `projects/<name>/gateway.state` |
| `jobs/<id>.json` | `jobs/<id>.job` |
| `trash/<name>.json` | `trash/<name>.trash` |
| `config.json` | `config` |
| — | `state-version` (contains `2`) |
| — | `events.log` — append-only TSV activity feed |

## Why

- **No `jq` at runtime.** ~132 call sites became bash string operations;
  startup went from ~250 ms to ~25 ms.
- **Watchable state.** One file per worktree means a consumer (`pwt-ui`,
  a statusline) gets a precise filesystem event and re-reads one small file
  instead of re-parsing a growing blob.
- **Safer writes.** `meta set` rewrites one small file atomically instead of
  the whole database.

## Running it

```bash
pwt state migrate --check     # dry run: counts + anything that would be skipped
pwt state migrate             # apply
pwt state migrate --verify    # confirm counts match
```

It also runs automatically on the first command after upgrading.

`--check` reports one line per source, for example:

```
meta.json          118 records → 111 worktrees, 7 skipped (malformed)
projects/*/config   12 files   → 12 configs
jobs/*.json         35 files   → 35 job records
```

**Read the "skipped" count.** Skips are malformed legacy records — most
often a worktree written at project level, which older pwt versions could
produce. They stay in `meta.json.v1.bak` and can be re-added by hand with
`pwt meta set`. A skip is never silent: each entry is named.

## Rollback

Every source is preserved as `*.v1.bak`:

```bash
rm ~/.pwt/state-version
find ~/.pwt -name '*.v1.bak' | while read -r f; do mv "$f" "${f%.v1.bak}"; done
```

Then use a pwt release from before schema 2 shipped. Remove the backups once you are
confident; `pwt doctor` keeps reminding you they exist.

## What external consumers must update

This is the part that breaks quietly. Anything reading pwt's state files
directly — Pwtfiles, statuslines, dashboards, scripts — must change, because
the old globs simply match nothing and loops fall through without an error.

```bash
# Before — matches nothing after the migration, stops nothing, reports nothing
for f in "$PWT_DIR/jobs"/*.json; do
    [ -f "$f" ] || continue
    id=$(grep -o '"id": *"[^"]*"' "$f" | ...)
done

# After — supported interface, stable across schema versions
pwt jobs list --porcelain | jq -r '.[] | select(.status=="running") | .id'
```

Prefer these over reading files:

| Need | Use |
|---|---|
| Background jobs | `pwt jobs list --porcelain` |
| Worktrees | `pwt list --porcelain` |
| One worktree | `pwt info <wt> --porcelain` |
| Everything at once | `pwt state --json` |

If you must read files (a long-running watcher, where per-command startup
cost matters), check `~/.pwt/state-version` first and refuse on an
unexpected value — see [state-v2-contract.md](../state-v2-contract.md).

## Known failure modes

| Symptom | Cause | Fix |
|---|---|---|
| `legacy pwt state (v1 JSON) found, but jq is not installed` | Migration needs `jq` once | Install `jq`, re-run any pwt command — or start fresh with `mv ~/.pwt ~/.pwt.old` |
| Fewer worktrees than expected after migrating | Malformed legacy entries were skipped | Check the named skips; recover from `meta.json.v1.bak` with `pwt meta set` |
| `pwt` sees an empty world after switching builds | `state-version` exists but state was never converted (two builds writing to the same `~/.pwt`) | `rm ~/.pwt/state-version` and run `pwt state migrate --check`, then `pwt state migrate` |
| A Pwtfile command silently stops working | It reads state files directly | Switch it to a `--porcelain` interface (see above) |
